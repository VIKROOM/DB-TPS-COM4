REVISION ESTATICA · U6/U7/U8
==========================================================================

H10 (U6) restore_test.ps1: usa --no-owner/--no-privileges=True; verifica roles/grants despues de restaurar=False
   Detectado: la restauracion valida datos e integridad, pero no
   comprueba que los roles ni los GRANT se hayan restaurado.

H11 (U6) backup_foodstore.ps1: retencion por LastWriteTime=True; parametro RetencionDias=True
   Detectado: copiar o restaurar archivos cambia la fecha de
   modificacion y puede alterar que respaldos se conservan.

H12 (U7) 01_exportar_pedidos_mongodb.sql: usa replace()=True; escapa barras invertidas=False
   Detectado: solo se escapan comillas dobles; un nombre con
   barra invertida o salto de linea generaria JavaScript invalido.

H13 (U7) 01_crear_coleccion.js: db.pedidos.drop()=True
   Detectado: idempotente en laboratorio, pero destructivo si se
   ejecuta sobre una base ya poblada.

H14 (U8) importar_snapshot.sql referencia importar_snapshot.py=True; el archivo existe=False
   Detectado: comentario con una alternativa inexistente.

H15 (U8) rutas temp de usuario Windows fijas: simular_tp8.py=True; revision_codigo.py=True
   Detectado: la ruta de PGDATA no es portable a otra cuenta.
   simular_tp8.py contiene una ruta literal C:\Users\...
   revision_codigo.py contiene una ruta literal C:\Users\...

H16 (U8) importar_snapshot.sql usa .import=True; simular_tp8.py usa .import=False
   Detectado: el .sql depende del cliente sqlite3 y el runner
   Python importa el CSV por otra via; son dos caminos distintos.

H17 (U6) maintenance.sql usa DROP TABLE IF EXISTS tmp_mantenimiento=True; califica pg_temp=False
   Detectado: sin calificar el esquema, podria borrar una tabla
   permanente llamada tmp_mantenimiento si existiera.

CONCLUSION
==========================================================================
H1 ACEPTADO: app_web/roles de app tienen SELECT de tabla sobre usuario;
   el minimo privilegio por columna solo se aplico a rol_soporte.
H2 ACEPTADO: usuario_anon no tiene PK ni NOT NULL; el INSERT duplicado
   paso y la verificacion por EXCEPT siguio dando diff_total = 0.
H3 ACEPTADO: v_pedidos_cliente devuelve menos pedidos que la tabla;
   el pedido del cliente inactivo desaparece del historial.
H4 ACEPTADO: U5 referencia usuario/detalle_pedido; el esquema U3 tiene
   cliente/linea_pedido. El GRANT falla con 'relation does not exist'.
H5 DESCARTADO: la secuencia avanza, pero el pedido no queda huerfano
   porque RAISE EXCEPTION aborta la transaccion. Los huecos de una
   secuencia son esperables y no afectan integridad ni negocio.
H6 ACEPTADO: ALTER DEFAULT PRIVILEGES ... GRANT SELECT (columna)
   no es valido en PostgreSQL ('default privileges cannot be set
   for columns'); el script U5 se corta en esa linea. Se propone
   quitar la lista de columnas del default privilege y mantener el
   grant por columna solo en la tabla existente, o crear una vista
   usuario_soporte y otorgar SELECT sobre la vista.
H7 ACEPTADO: tp_fnbc_control_lote.sql hace DROP TABLE y recrea el
   ejemplo; sobre una base real borra filas. Se corrige con
   tp_fnbc_control_lote_migracion_segura.sql (backup + BEGIN/COMMIT
   + verificacion + ROLLBACK), documentado en kiro/design.md.
H8 ACEPTADO: U4 usa detalle_pedido y el esquema final define
   linea_pedido; el trigger falla. Se propone vista de
   compatibilidad detalle_pedido (como en U6) o renombrar en U4.
H9 ACEPTADO: la migracion segura aborta con RAISE EXCEPTION ante
   una violacion de DF2 y el ROLLBACK no deja objetos nuevos; la
   tabla original y el backup conservan sus filas.
H10 ACEPTADO (limitacion): restore_test.ps1 usa --no-owner y
   --no-privileges; valida datos e integridad, no roles/GRANT. Se
   documenta y se propone una verificacion posterior de privilegios.
H11 ACEPTADO (mejora menor): la retencion por LastWriteTime puede
   desalinearse si los archivos se copian; usar la fecha del nombre.
H12 ACEPTADO: la exportacion a MongoDB escapa comillas dobles pero
   no barras invertidas ni saltos de linea; usar json_build_object
   o escapar tambien '\\' y '\n' antes de generar el JavaScript.
H13 ACEPTADO (laboratorio): db.pedidos.drop() es intencional para
   idempotencia; documentar que no debe ejecutarse en produccion.
H14 ACEPTADO: el comentario referencia importar_snapshot.py, que no
   existe; corregir el comentario o agregar el script Python.
H15 ACEPTADO: la ruta PGDATA esta fijada a una cuenta Windows; usar
   tempfile.gettempdir() para que sea portable.
H16 DESCARTADO: importar_snapshot.sql es para el cliente sqlite3 y
   simular_tp8.py importa el CSV por Python; son caminos distintos
   y el runner cubre la reproducibilidad. Se documenta la diferencia.
H17 ACEPTADO (bajo riesgo): calificar la tabla temporal como
   pg_temp.tmp_mantenimiento para no borrar una tabla homonima.
